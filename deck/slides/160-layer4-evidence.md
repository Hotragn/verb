## Six things every decision has to carry.

<div class="cols">
<div>
<ol>
<li><strong>What was decided.</strong> One sentence, naming the thing.</li>
<li><strong>What it rested on.</strong> The actual sources, not a summary.</li>
<li><strong>What was rejected, and why.</strong></li>
</ol>
</div>
<div>
<ol start="4">
<li><strong>How confident, and how it would be wrong.</strong> Named, not hedged.</li>
<li><strong>How to undo it,</strong> what that costs, and how long it stays cheap.</li>
<li><strong>Who is accountable.</strong> A person, not a team.</li>
</ol>
</div>
</div>

<blockquote>A decision missing any of the six is not a decision. It is an output.
Outputs do not get actioned.</blockquote>

<div class="margin"><b>Why this list</b><br>
Every field exists to make the next review faster. Field two alone is most of the
saving, because it is the reviewer not re-gathering what the agent already had.</div>

@notes

The point people miss: this is not an audit trail. An audit trail is built for
reconstructing the past months later. This is built for making the next review
fast this afternoon. Those two goals produce different documents and only one of
them changes the budget.

The evidence for field two: ask any reviewer where the time goes on a hard
review. It is not the judgement, it is re-finding the inputs. Typically half.

Field three has a subtle mechanism worth explaining if you have time. Without it,
the reviewer's question is "is this right", which is unbounded. With it, the
question becomes "is one of these rejection reasons wrong", which is a list you
can get to the end of.
