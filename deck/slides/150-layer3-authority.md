## Authority is set by blast radius, not by confidence.

| authority level | the test that puts you here | examples |
|---|---|---|
| Agent acts, logs only | Reversible within a day, nobody outside affected | Reassign a task, update a date, flag a duplicate |
| Agent acts, human notified | Reversible within a week, internal only | Reallocate slack, reorder a backlog, redraft a summary |
| Agent proposes, one human approves | Reversible with effort, or affects one team's plan | Move a milestone, change a resource split |
| Agent proposes, a committee approves | Hard to reverse, or touches cost, contract or compliance | Budget reallocation, vendor change, scope reduction |
| Human decides, agent supports only | Irreversible, or legally accountable | Contract signature, termination, regulatory submission |

<p class="small"><strong>Notice what is absent.</strong> Model confidence appears
nowhere on this table. Confident and wrong on an irreversible decision is still a
disaster, and a confidence score is the agent marking its own work.</p>

@notes

The ladder is easy to follow, so spend your time on the last line instead.

Almost every governance framework people have seen gates on confidence: high
confidence gets more autonomy. Say why that is backwards. Confidence is the
agent's opinion of itself, and it is exactly as trustworthy as the thing you were
trying to check. Blast radius is a property of the decision, and it is knowable
before the agent runs.

If somebody asks how this relates to the four classes: classes tell you what
checking costs, blast radius tells you what happens if you get it wrong. Class
sizes the budget, blast radius sets the authority. You need both, and they are
not the same axis.

The practical version: you can build this table in an afternoon with your
existing delegated authority matrix. Most organisations already have one for
spend. This is the same idea pointed at reversibility.
