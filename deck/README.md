# The deck

The talk, as one self-contained HTML file.

```bash
python deck/build.py
```

Then open `deck/index.html`. No install, no server, no network requests. It works on a laptop with the wifi switched off, which is the only condition that actually matters at a conference.

| Key | Does |
|---|---|
| arrows, space | next and previous |
| `o` or `Escape` | overview of every slide, click to jump |
| `s` | speaker notes |
| `f` | fullscreen |
| a number | jump to that slide |

Add `?print` to the URL and use the browser print dialogue to export a PDF, one slide per page.

## What is where

```
slides/           the source. One markdown file per slide, in filename order.
  18-final.md     the closing slide
assets/           QR codes, generated by build.py
SCRIPT.md         the spoken script, with timings
build.py          compiles slides into index.html
index.html        the built deck. Committed, so a fresh clone can open it.
```

Edit a file in `slides/`, re-run `build.py`, reload. Front matter is a few `key: value` lines before a `---`. Everything after `@notes` becomes a speaker note. `{{REPO_URL}}` and friends are substituted from the constants at the top of `build.py`, which is the one place to change a link.

## QR codes

Generated at build time by [`tools/qr.py`](../tools/qr.py), a QR encoder written from scratch in the standard library. Not fetched from a QR web service, for two reasons: the build should not depend on the uptime of a third party, and the URLs should not travel to one to be turned into a picture.

They are written to `assets/` as SVG files, so they can be dropped into any other tool, and inlined into `index.html` as data URIs, so the deck stays one portable file when it is emailed or copied to a memory stick.

The encoder is checked three ways in `tests/test_qr.py`: the Reed-Solomon codewords must have zero syndromes, the finished matrix must decode back to the input, and the structural patterns must sit where the specification says. An encoder that produces a plausible-looking but unscannable square is worse than no encoder.

## Visual direction

Derived from the information design principles of Edward Tufte rather than from a slide template. Tufte is a Yale professor emeritus and the most cited authority on presenting quantitative information, and his principles are the right ones for a talk that is mostly numbers and definitions:

- **Show the content.** One idea per slide, and the slide carries the idea rather than a summary of the speech.
- **High content-to-ink ratio.** Hairline rules instead of boxes. No shadows, no gradients, no decorative shapes, nothing that is not carrying meaning.
- **Erase what does not inform.** No logo on every slide, no template furniture, no bullet points where a sentence would do.
- **Use the margin.** A narrow right-hand column carries the second voice, which is where a caveat or a definition goes without interrupting the main line.
- **Type does the work.** Serif for prose, mono for every number, so figures line up in columns and can be compared down a page.

This is a derivation, not a copy. The palette is Meter, which belongs to this repository, and the colour coding of the four decision classes carries meaning rather than decoration.

No webfont is loaded. The type is a system serif stack, so the deck renders identically offline and there is no flash of unstyled text mid-sentence.

## Using reveal.js instead

The markup is reveal.js compatible: slides are `<section>` elements and speaker notes are `<aside class="notes">`. Drop a reveal.js distribution into `deck/vendor/`, swap the `<style>` and `<script>` blocks in `build.py` for the vendored files, and everything else carries over.

The built-in engine exists so that the deck has no dependencies at all. It covers what a talk needs and nothing more.
